\phantomsection
\subsection*{Objective}
\addcontentsline{toc}{subsection}{Objective}

Study and empirically analyse two fundamental graph traversal algorithms: Depth First
Search (DFS) and Breadth First Search (BFS), evaluating their execution time across
different graph types and input sizes.

\phantomsection
\subsection*{Tasks:}
\addcontentsline{toc}{subsection}{Tasks}

\begin{enumerate}[itemsep=1pt]
  \item Implement DFS (recursive variant) and BFS in Python;
  \item Establish the properties of the input data against which the analysis is performed;
  \item Choose metrics for comparing the algorithms;
  \item Perform empirical analysis of the proposed algorithms;
  \item Make a graphical presentation of the obtained data;
  \item Draw conclusions on the work done.
\end{enumerate}

\phantomsection
\subsection*{Theoretical Notes:}
\addcontentsline{toc}{subsection}{Theoretical Notes}

\hspace{0.7cm} Empirical analysis complements theoretical complexity analysis by measuring actual
program behaviour on a real machine. It is particularly valuable when:

\begin{itemize}[itemsep=1pt]
  \item the theoretical bounds differ only by constant factors;
  \item the algorithm's performance depends heavily on the structure of the input (e.g.\ graph
  density, connectivity, diameter);
  \item comparing two algorithms with the same asymptotic complexity to find which is faster
  in practice.
\end{itemize}

The general empirical methodology followed in this work is:

\begin{enumerate}[itemsep=1pt]
  \item Define the analysis goal and select the efficiency metric.
  \item Identify the input properties: graph type, number of nodes $n$, edge density.
  \item Implement the algorithms.
  \item Generate multiple representative input data sets.
  \item Execute the program for each data set and record the measurement.
  \item Analyse and visualise the collected data.
\end{enumerate}

\phantomsection
\subsection*{Introduction:}
\addcontentsline{toc}{subsection}{Introduction}

\hspace{0.8cm} Graph traversal is one of the most fundamental operations in computer science.
DFS and BFS are two complementary strategies that visit every vertex of a graph exactly once,
differing only in the order in which vertices are explored.

Both algorithms have the same asymptotic time complexity of $O(V + E)$, where $V$ is the number
of vertices and $E$ is the number of edges.

This laboratory work investigates these practical differences by measuring wall-clock execution
time across nineteen distinct graph classes, covering sparse, dense, structured, directed,
multi-edge, weighted, and regular topologies.

\phantomsection
\subsection*{Comparison Metric:}
\addcontentsline{toc}{subsection}{Comparison Metric}

\hspace{0.8cm} The primary metric is \textbf{execution time measured in milliseconds}
(wall-clock time, averaged over three independent repetitions to reduce measurement noise).
The error margin is estimated at $\pm 2.5$\,ms.

DFS and BFS both run in $O(V + E)$ time, so the quantity of interest is the \emph{constant
factor} difference introduced by the different internal data structures and traversal orders.

\phantomsection
\subsection*{Input Format:}
\addcontentsline{toc}{subsection}{Input Format}

\hspace{0.8cm} Graphs are represented as adjacency-list dictionaries
$\{v : [\text{neighbours}]\}$ with integer node labels $0, 1, \ldots, n{-}1$.
All graph families are benchmarked using the same standard sizes
$n \in \{100, 200, 300, 400\}$.
Twelve graph classes are used, covering a wide spectrum of topologies:

\begin{enumerate}[itemsep=2pt]
  \item \textbf{Path / Chain} -- a single linear chain $0 - 1 - 2 - \cdots - (n{-}1)$;
  $E = n-1$. Highlights the worst case for DFS stack depth.

  \item \textbf{Cycle} -- a single cycle $0 - 1 - \cdots - (n{-}1) - 0$;
  $E = n$. Every node has degree 2; structurally similar to a path with one extra edge.

  \item \textbf{Complete} -- $K_n$, every pair of nodes is connected;
  $E = \binom{n}{2} = O(n^2)$.

  \item \textbf{Star} -- a central hub node connected to all $n-1$ leaves;
  $E = n-1$, diameter $= 2$. BFS finishes in two levels; DFS must push $n-1$
  neighbours onto its stack at once.

  \item \textbf{Complete Bipartite} -- $K_{n/2,\,n/2}$; two disjoint sets where every
  node in one set is connected to every node in the other; $E = (n/2)^2 = O(n^2)$.

  \item \textbf{Binary Tree} -- a balanced binary tree of depth
  $\lfloor \log_2 n \rfloor$; $E = V - 1$. DFS follows branches to maximum depth
  before backtracking; BFS visits level by level.

  \item \textbf{Forest} -- two balanced binary trees connected by a single bridge
  edge; $E = V - 1$. Tests how both algorithms handle a bottleneck edge separating
  two components.

  \item \textbf{DAG (Directed Acyclic Graph)} -- a directed chain with skip edges:
  $i \to i{+}1$ and $i \to i{+}2$; $E \approx 2n$. Demonstrates traversal on
  directed graphs without cycles.

  \item \textbf{Directed Cycle} -- a directed cycle with additional shortcut
  edges $i \to i{+}2$ for even $i$; $E \approx 1.5\,n$. The cycle ensures every
  node is reachable from every other node.

  \item \textbf{Grid} -- a $\lfloor\sqrt{n}\rfloor \times \lfloor\sqrt{n}\rfloor$
  2-D lattice; each interior node has degree 4. BFS frontier expands as a diamond;
  DFS spirals deeply before backtracking.

  \item \textbf{Sparse Random} -- Erd\H{o}s--R\'enyi $G(n,\,0.2)$, kept connected;
  $E \approx 0.1\,n^2$.

  \item \textbf{Dense Random} -- Erd\H{o}s--R\'enyi $G(n,\,0.7)$;
  $E \approx 0.35\,n^2$.

  \item \textbf{Simple Graph} -- a connected sparse undirected graph
  (Erd\H{o}s--R\'enyi $G(n,\,0.15)$) with no self-loops and no parallel edges;
  the canonical definition of a graph. Serves as a baseline for unstructured
  sparse connectivity.

  \item \textbf{Multigraph} -- an undirected graph where pairs of nodes may share
  more than one edge; built on a path backbone with every edge duplicated.
  For DFS/BFS the parallel edges are collapsed to a simple graph, so the
  traversal comparison reflects how multi-edge density affects neighbour-list size.

  \item \textbf{Pseudograph} -- extends the multigraph by additionally allowing
  self-loops ($i \to i$). Self-loops are removed before traversal; the comparison
  highlights how pseudo-topologies compare to their simple-graph equivalents.

  \item \textbf{Directed Multigraph} -- a directed graph with parallel arcs;
  built on a directed path backbone with every arc duplicated. Collapsed to a
  simple digraph for traversal.

  \item \textbf{Wheel} -- a hub node connected to all nodes of a $(n{-}1)$-cycle;
  $E = 2(n-1)$. Combines star-like properties (one centre) with a surrounding ring.

  \item \textbf{Regular Graph} -- a 3-regular (cubic) graph where every node has
  exactly degree~3. Generated via \texttt{nx.random\_regular\_graph}; $E = 3n/2$.
  Uniform degree removes topology-driven variance and isolates constant-factor
  differences between DFS and BFS.

\end{enumerate}

% ----------------------------------------------------------------
\phantomsection
\subsection*{Depth First Search (DFS)}
\addcontentsline{toc}{subsection}{Depth First Search (DFS)}

\hspace{0.8cm} DFS explores a graph by going as deep as possible along each branch before
backtracking. In this implementation, DFS uses Python's call stack (recursive variant).

\noindent\hspace*{0.8cm}\textit{Theoretical Complexity:}

\begin{itemize}[itemsep=1pt]
  \item \textbf{Time:} $O(V + E)$ -- each vertex is pushed and popped from the stack once;
  each edge is examined once (undirected: twice, once per endpoint).
  \item \textbf{Space:} $O(V)$ -- the stack holds at most $V$ elements (depth of the deepest
  reachable path from the source).
\end{itemize}

\noindent\hspace*{0.8cm}\textit{Algorithm Description:}

\begin{lstlisting}[caption={DFS -- Recursive pseudocode}, label={lst:dfs-iter}]
DFS_Recursive(graph, v, visited, order):
  visited.add(v)
  order.append(v)

  for neighbour in graph[v]:
    if neighbour not in visited:
      DFS_Recursive(graph, neighbour, visited, order)

  return order
\end{lstlisting}


\noindent\hspace*{0.8cm}\textit{Python Implementation:}

\begin{lstlisting}[language=Python, caption={Recursive DFS (main.py, comp.py)},
                   label={lst:dfs-py}]
def dfs(graph, start, visited=None, path=None):
  if visited is None:
    visited = set()
  if path is None:
    path = []
  visited.add(start)
  path.append(start)
  for neighbor in graph[start]:
    if neighbor not in visited:
      dfs(graph, neighbor, visited, path)
  return path
\end{lstlisting}

\noindent\hspace*{0.8cm}\textit{Results:}

On sparse random and tree graphs, DFS execution time grows linearly with $n$, consistent
with the $O(V + E)$ bound. On path graphs, DFS must push and pop $n$ elements sequentially
(stack depth $= n$), introducing a noticeable constant-factor overhead compared to BFS.

\noindent\hspace*{0.8cm}\textit{Optimizations:}

\begin{itemize}[itemsep=1pt]
  \item \textbf{Recursive implementation simplicity} provides a direct and compact mapping
  of the DFS idea (visit node, recurse into unvisited neighbours).
  \item \textbf{Raised recursion limit} (configured in \texttt{main.py}) reduces the risk
  of recursion-depth errors on deep path-like graphs.
  \item \textbf{Early termination} can be added for goal-directed search: halt as soon as
  the target vertex is dequeued.
\end{itemize}

\phantomsection
\subsection*{Breadth First Search (BFS)}
\addcontentsline{toc}{subsection}{Breadth First Search (BFS)}

\hspace{0.8cm} BFS explores a graph level by level using a FIFO queue. It guarantees that
the first time a node is visited it has been reached via the \emph{shortest path}
(minimum number of hops) from the source node.

\noindent\hspace*{0.8cm}\textit{Theoretical Complexity:}

\begin{itemize}[itemsep=1pt]
  \item \textbf{Time:} $O(V + E)$ -- each vertex is enqueued and dequeued exactly once;
  each edge is examined once per endpoint.
  \item \textbf{Space:} $O(V)$ -- the queue may hold an entire BFS frontier layer, which in
  the worst case (e.g.\ star or complete graph) contains $O(V)$ nodes simultaneously.
\end{itemize}

\noindent\hspace*{0.8cm}\textit{Algorithm Description:}

\begin{lstlisting}[caption={BFS pseudocode}, label={lst:bfs}]
BFS(graph, start):
    visited = {start}
    queue   = deque([start])
    order   = []

    while queue is not empty:
        v = queue.popleft()
        order.append(v)
        for neighbour in graph[v]:
            if neighbour not in visited:
                visited.add(neighbour)
                queue.push_right(neighbour)

    return order
\end{lstlisting}

\noindent\hspace*{0.8cm}\textit{Python Implementation:}

\begin{lstlisting}[language=Python, caption={BFS (main.py, comp.py)}, label={lst:bfs-py}]
from collections import deque

def bfs(graph: dict, start) -> list:
    visited = {start}
    queue   = deque([start])
    order   = []
    while queue:
        v = queue.popleft()
        order.append(v)
        for neighbour in graph.get(v, []):
            if neighbour not in visited:
                visited.add(neighbour)
                queue.append(neighbour)
    return order
\end{lstlisting}

\noindent\hspace*{0.8cm}\textit{Results:}

BFS execution time also grows linearly in $n$. On path graphs, the BFS frontier is at most
two nodes wide at every step; consequently, BFS is faster than DFS on paths because
\texttt{deque.popleft()} costs $O(1)$ and the queue never grows large. On dense graphs
both algorithms slow down due to the $O(V^2)$ edge set.



\noindent\hspace*{0.8cm}\textit{Optimizations}

\begin{itemize}[itemsep=1pt]
  \item \textbf{\texttt{collections.deque}} provides $O(1)$ \texttt{popleft()} -- a plain
  Python list would give $O(n)$ for the same operation.
  \item \textbf{Mark visited on enqueue} (not on dequeue) prevents the same node from being
  added to the queue multiple times, reducing work by a factor proportional to average degree.
  \item \textbf{Bidirectional BFS} can reduce shortest-path search space from $O(b^d)$ to
  $O(b^{d/2})$ on large graphs with high branching factor $b$ and shortest-path length $d$.
\end{itemize}

\subsubsection*{1.\quad Path / Chain Graph}

A path graph is a single linear chain $0 - 1 - 2 - \cdots - (n{-}1)$ with $E = n - 1$
edges. Every node except the endpoints has degree~2.

\textit{DFS behaviour.} Starting from node~0, DFS walks the entire chain without ever
backtracking, pushing one neighbour onto the stack at each step. The stack depth grows
linearly to~$n$, which causes Python list re-allocations on large inputs.

\textit{BFS behaviour.} BFS also walks left to right, but its queue never holds more
than two elements at any step (the current frontier is at most one node wide). This
makes BFS measurably faster on paths ($\sim$20--30\% at $n = 400$).

\subsubsection*{2.\quad Cycle Graph}

A cycle graph connects nodes in a ring: $0 - 1 - \cdots - (n{-}1) - 0$, adding one
edge compared to a path. Every node has exactly degree~2.

\textit{DFS behaviour.} DFS picks one direction and follows the ring all the way
around; the stack depth reaches $n$ just as on a path.

\textit{BFS behaviour.} BFS also proceeds along the ring; the queue holds at most
two nodes. The performance profile is nearly identical to the path case.

\subsubsection*{3.\quad Complete Graph}

In a complete graph $K_n$ every pair of nodes shares an edge, giving
$E = \binom{n}{2}$. Every node has degree~$n - 1$.

\textit{DFS behaviour.} From the start node, DFS pushes $n - 1$ neighbours onto the
stack, then picks one, pushes its $n - 2$ unvisited neighbours, and so on. The stack
grows to $O(n)$ and every adjacency list is fully scanned, making the total work
$O(n^2)$.

\textit{BFS behaviour.} BFS enqueues all $n - 1$ neighbours at the first step and
visits them level by level (depth~1 for all). The queue peaks at $n - 1$ entries.
Because \texttt{deque} operations are slightly more cache-friendly than list-stack
push/pop, BFS is marginally faster.

\subsubsection*{4.\quad Star Graph}

A star graph has a single hub node~0 connected to $n - 1$ leaf nodes;
$E = n - 1$, diameter $= 2$.

\textit{DFS behaviour.} DFS visits the hub, pushes all $n - 1$ leaves, then pops
them one by one. Each leaf has no unvisited neighbours so it immediately backtracks.
Traversal finishes in $2(n-1)$ stack operations.

\textit{BFS behaviour.} BFS visits the hub, enqueues all leaves (one BFS level),
then dequeues each leaf. The queue peaks at $n - 1$ entries. Both algorithms
perform almost identically.

\subsubsection*{5.\quad Complete Bipartite Graph}

A complete bipartite graph $K_{n/2,\,n/2}$ has two node sets where every node in
one set is connected to every node in the other; $E = (n/2)^2 = O(n^2)$.

\textit{DFS behaviour.} From a node in set~A, DFS pushes all $n/2$ nodes of set~B,
then from each B-node pushes all unvisited A-nodes. The pattern alternates deeply.

\textit{BFS behaviour.} BFS visits set~A (level~0), then all of set~B (level~1),
then remaining A-nodes (level~2). The queue peaks at $n/2$. As with the complete
graph, the $O(n^2)$ edge count dominates execution time.

\subsubsection*{6.\quad Binary Tree}

A balanced binary tree of depth $\lfloor\log_2 n\rfloor$; $E = V - 1$.
The maximum degree is~3 (parent + two children).

\textit{DFS behaviour.} DFS dives to the leftmost leaf (depth $\log n$), backtracks
one level, visits the right subtree, and repeats. The stack depth equals the tree
height $O(\log n)$, which is very memory-efficient.

\textit{BFS behaviour.} BFS visits nodes level by level; the queue width doubles at
each level, peaking at $\sim n/2$ on the last level. For large trees, BFS therefore
uses more transient memory than DFS.

\subsubsection*{7.\quad Forest (Two Trees with Bridge)}

Two balanced binary trees are connected by a single bridge edge, giving $E = V - 1$.
The bridge creates a bottleneck between the two components.

\textit{DFS behaviour.} DFS fully explores one tree before crossing the bridge,
then explores the second tree. The stack depth is bounded by the height of the
larger tree.

\textit{BFS behaviour.} BFS discovers the bridge node only when the frontier
reaches the root of the second tree. The two components are explored
level-by-level in sequence. Performance is comparable to a single tree of
the same total size.

\subsubsection*{8.\quad Directed Acyclic Graph (DAG)}

A DAG built as a directed chain $0 \to 1 \to \cdots \to (n{-}1)$ with
additional skip edges $i \to i{+}2$; $E \approx 2n$. The graph has no
cycles and a clear topological order.

\textit{DFS behaviour.} DFS follows the chain forward. Each node has at most
two outgoing edges, so the behaviour resembles path traversal. Because edges
are directed, the traversal never revisits earlier nodes.

\textit{BFS behaviour.} BFS proceeds similarly; each level moves one or two

small constant factors.

\subsubsection*{9.\quad Directed Cycle}

\textit{DFS behaviour.} DFS follows one direction around the cycle, with
occasional shortcuts. The cycle back-edge is encountered but discarded
because the source has already been visited.

\textit{BFS behaviour.} BFS also proceeds around the ring, potentially
reaching nodes via shortcuts one step earlier. Both algorithms visit
all $n$ nodes in $O(V + E)$ time.

\textit{BFS behaviour.} BFS expands as a diamond-shaped frontier from the

\subsubsection*{17.\quad Wheel Graph}

A wheel graph $W_n$ connects a single hub node to every node of an $(n{-}1)$-cycle;
$E = 2(n{-}1)$. Every spoke and rim edge provides two paths between any two rim
nodes (via the hub or via the rim), making the diameter of $W_n$ equal to~2 for the
hub and at most~3 between rim nodes.

\textit{DFS behaviour.} Starting from the hub, DFS pushes all $n - 1$ rim nodes
onto the stack, then traverses the rim chain from one end. The stack peaks at
$O(n)$ but the adjacency-list scans are light.

\textit{BFS behaviour.} BFS visits the hub (level~0) and all rim nodes (level~1)
in a single step, making the queue peak at $n - 1$ and completing traversal
in two levels. BFS is measurably faster on wheels because of the extremely
short diameter.

\section*{CONCLUSION}
\addcontentsline{toc}{section}{CONCLUSION}

\hspace{0.8cm} Through this empirical study, both DFS and BFS were implemented and evaluated
across nineteen representative graph categories, covering sparse, dense, structured, directed,
multi-edge, weighted, and regular topologies.

Both algorithms share the same asymptotic complexity of $O(V + E)$, and the empirical
measurements confirm linear growth in execution time as the number of nodes increases
for all graph types where $E = O(V)$ (path, cycle, star, binary tree, forest, DAG,
directed cycle, grid, simple, multigraph, pseudograph, directed multigraph, wheel,
regular, weighted). On dense topologies ($E = O(V^2)$), complete, bipartite, dense
random, both algorithms exhibit super-linear growth dominated by edge scanning.

The constant-factor differences observed in practice are driven mainly by the interaction
between data-structure overhead and graph topology. Python's \texttt{collections.deque},
used by BFS, provides stable $O(1)$ front removals and good block-based locality, while
the recursive DFS implementation relies on Python's call stack, where function-call overhead
and recursion depth can become relevant on long path-like traversals. Topology then amplifies or
reduces these effects: on path and cycle graphs DFS maintains a stack proportional to
path length while BFS keeps a narrow queue; on star and wheel graphs BFS completes in
only two levels while DFS must still visit all nodes sequentially; on balanced trees DFS
retains only logarithmic-depth state while BFS can temporarily hold a large last-level
frontier; on multigraphs and pseudographs the collapsed simple structure behaves like a
sparse graph with chords; on regular graphs the uniform degree minimises DFS/BFS
differences; and on dense graphs the dominant cost becomes edge scanning, which largely
equalises the two algorithms.

From a practical perspective, DFS remains especially suitable for structure-oriented tasks
such as cycle detection, topological reasoning, connected-component exploration, and
backtracking-style searches where deep exploration is useful. BFS is preferable when
shortest-hop paths are required, when level-order discovery is important, or when the
target is expected to be close to the source in terms of graph distance. Weighted graphs
require dedicated algorithms such as Dijkstra or Bellman-Ford for shortest-path queries;
DFS and BFS provide only unweighted traversal on such structures. Therefore, the
most effective strategy is topology-aware selection rather than rigid preference: BFS often
provides better constants on path-like, wheel, and grid inputs, whereas DFS is often a
strong choice for tree traversal and connectivity analysis.

In summary, for most general-purpose traversal tasks DFS and BFS perform comparably.
The animated GIF visualisations generated for each graph type clearly show the contrasting
exploration orders: DFS dives deep before backtracking, while BFS expands outward
level by level.
